# データの完全性と来歴

> `AGENTS.md`「再現性」節から分けた詳細。外部データの取得・凍結・検証に関わる作業の前に読む。

### 外部データソースの再現性ハイアラーキ

ライブな外部ソース（API、SPARQL、移動 ref、版が動くパッケージ）に依存する取得は、次の優先順で再現性を確保する。**バイトの凍結コピーは最終手段**。

1. **正典に pin して都度再取得**（最優先）: 版付き DOI/Zenodo、タグ付きリリース、CRAN の版＋SHA。re-derivable かつ再現可能
2. **移動 ref を不変識別子に固定**: `master`/`latest` → commit SHA。上流は正典のまま状態だけ固定
3. **バイトを凍結**（最終手段）: 上流が再現可能なハンドルを持たないときのみ（時間遡及不可の SPARQL、版の無い API、force-push される ref）

- どの段でも**正典からの再導出スクリプト（provenance）を必ず残す**。ライブ取得は retry＋fail-loud（`purrr::safely()` で握り潰さない）
- 凍結・pin したら下流を再ビルドし、論文時の値とバイト一致を検証する（`pointblank::row_count_match()` 等でドリフトを fail-loud 化）

### 凍結データの provenance 検証

`data-raw/` に凍結した不変データは、`data-raw/PROVENANCE.md` の manifest（`file` / `sha256` / source / retrieved / license / 再導出経路）に記録する。パイプラインでは `R/data_provenance.R` の `verify_provenance(path, sha256)` を `format = "file"` ターゲットに挟み、読み込み前に sha256 を fail-loud 検証する（例: `_targets.R` の `example_raw_file`）。共同研究者が別コピーを持っていても、ここで停止する。

### 「取れなかった」を「無かった」にしない

`R/input_guards.R` は、**入力の不在が空の結果に化ける**のを境界で止める汎用ヘルパー。provenance 検証（バイトが変わったか）とは別の問題を扱う。同じ「0 件」に見える 2 つの失敗があり、どちらも単独では例外を出さない。

- **ローカルの入力パスが違う**: `list.files()` が誤ったパスに `character(0)` を返すと、読み込みは **0 行かつ 0 列**のデータフレームを作り、意味的検証は「キー列が全部無い」と報告する。**供給側のヘッダードリフトのように読めるが、実際の原因は上流のディレクトリ改名**。「列が無い」と言われたらスキーマより先に `dir.exists()` を疑う。`require_input_dir()` / `list_input_files()` を読み込みの手前に置き、ディレクトリが空という主張は `allow_empty = TRUE` で**呼び出し側に明示させる**
- **取得が失敗した**: ネットワークエラーと「照会したが該当なし」は、どちらも 0 件を残す。`n = 0` として記録すると**後から「存在しない証拠」として読まれる**。`new_fetch_result()` は 4 値 status（`ok` / `empty` / `absent` / `failed`）を強制し、失敗を 0 件として保存できないようにする。`summarise_fetch_results()` は**失敗を分母から外し、その件数を併記**する（成功分だけで計算した率は母集団に対する率ではない）

検証器は**投入前にそれ自体を既知の答えを持つケースで単体テストする**（`tests/testthat/test-input-guards.R`）。良いケースで raise する検証器は作業を止め、悪いケースで通る検証器は誤った結果に**お墨付きを与える**ので検証器が無いより悪い。両方向を固定する。
